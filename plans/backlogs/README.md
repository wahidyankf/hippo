# Backlogs

This stage holds finished plans that have not started. Each lives in one kebab-case folder with no date prefix; the date arrives at completion, because it records when work landed rather than when someone had the idea.

A plan here is complete as a document while no code has moved. It says why the work exists, which options were weighed, which was chosen and on what grounds, how delivery will proceed, and what will prove it done. A folder still missing one of those is an idea in a plan's clothes, and it belongs in [`../ideas/`](../ideas/README.md).

## What a Folder Contains

`README.md`, `brd.md`, `prd.md`, `delivery.md`, `learnings.md`, and exactly one technical shape: a single `tech-docs.md`, or `tech-docs/README.md` with mapped companions where distinct responsibilities each deserve their own reading order. Never both shapes, and never an empty companion created in advance of having something to put in it. An `evidence/` folder appears only once delivery has produced evidence worth committing.

The contract is stated once, in [plan lifecycle](../../repo-governance/conventions/plan-lifecycle.md).

## Starting One

Check first that the plan still matches the repository. A plan queued two months ago may describe code that has since been rewritten, and starting it unread is how a plan quietly becomes fiction. Then move the folder unchanged into [`../in-progress/`](../in-progress/README.md), update its status, and update both stage indexes in that same change.
